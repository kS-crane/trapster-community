Try it

  • GET /robots.txt - static inline content
  • GET /status.txt - served from files/, no matching endpoint needed
  • GET /api/v1/user?id=1 - regex path + query-param matching
  • GET /api/v1/search?q=hello - the quote filter escaping reflected input
  • GET /redirect - a Location header rendered per-request
  • GET /api/v1/health - a custom HTTP/1.1 reason phrase ("Superb" instead of "OK")
  • GET /files/report.pdf twice - the second request gets a 304, matched against the ETag from the first
  • GET /api/v1/export.csv - a weak, hash-style ETag
  • POST /api/v1/login with username=admin&password=admin123 - form parsing, a per-request token via uuid(), and a reason phrase that follows the outcome
  • POST /api/v1/settings with body containing settings - a template overriding its own status code
  • Any WebDAV-style verb (e.g. PROPFIND) - handled by unknown_method
